## Раньше здесь была статья о Claude Cowork

Claude Cowork появился в январе 2026 года как «Claude Code без кода» -- первый агент Anthropic для тех, кто не пишет программ. Его собрали на том же движке, что и Claude Code: агент работал с папками на компьютере и отдавал готовые файлы. За восемь месяцев Cowork оброс задачами по расписанию, проектами и управлением компьютером, переехал в облако, на веб и мобильные, а в августе -- в боковую панель Chrome.

16 сентября 2026 года Cowork перестал быть отдельным режимом: его возможности встроены в обычный Claude. Переключаться между чатом и агентом больше не нужно -- Claude сам решает, ответить на вопрос или взять задачу в работу. Поэтому теперь мы рассказываем об агентных возможностях Claude в целом. Кейсы юристов, которые раньше были в этой статье, перенесены в статью [Агентные сценарии работы](./../agentnye-scenarii): почти любой из них сегодня можно повторить в любом современном агенте.

## Один агент -- несколько окон

У Claude один агентный движок и несколько точек входа к нему. По сути это разные [харнессы](./../upravlenie-agentami/harness) на общей основе: скиллы, коннекторы и плагины, подключенные к аккаунту, работают в каждом из них. Окна различаются тем, где идет работа, что агент видит и сколько контроля остается у вас.

## Работа с вашими файлами: папки в задачах и проектах

Главное, что отличает агентную работу от чата: агент работает не с приложенными файлами, а с папкой. В десктоп-приложении Claude можно дать доступ к папке на диске -- агент сам читает документы, раскладывает их, создает новые файлы и кладет результат туда же. Загружать и скачивать ничего не нужно.

**Папка в задаче.** Для разовой задачи достаточно подключить папку к разговору. Claude видит только подключенные папки, их список хранится в настройках в разделе доверенных папок (Trusted folders). 

**Папка в проекте.** Для дела, клиента или направления, с которым вы работаете постоянно, удобнее проект. Его можно создать из существующей папки или добавить папку (или несколько) в контекст проекта позже. У проекта свои инструкции, файлы, память и задачи по расписанию. Сам проект хранится в аккаунте, а папка и файлы остаются на компьютере: если проект заархивировать, файлы никуда не денутся. 

**Доступ работает, пока открыт десктоп.** Сам агент работает в облаке и дотягивается до компьютера только через Claude Desktop. Если приложение закрыто или компьютер выключен, задача продолжится, но к локальным файлам агент не попадет. Так же устроены локальные коннекторы, плагины с локальными MCP-серверами, встроенный браузер и управление компьютером.

### Как агент находит нужное

Документы не загружаются в [контекстное окно](./../../znakomstvo-s-nejrosetyami/kontekstnoe-okno) целиком. Агент работает с папкой как исследователь: смотрит структуру, ищет по тексту нужные фрагменты, читает только их, а объемные подзадачи отдает [субагентам](./../upravlenie-agentami/orkestraciya-i-subagenty) с отдельным контекстом. Практическое следствие: агент ориентируется по именам файлов и иерархии папок, поэтому осмысленные названия обеспечивают надежность механики поиска. Как устроить рабочую папку -- в статье [Рабочее пространство агента](./../upravlenie-agentami/rabocheye-prostranstvo).

### Папочная архитектура: подход Константина Р.

Один из выпускников курса [«Нейросети для юриста: от основ к системе»](https://runetlex-academy.ru/neuralnetworks) поделился инструкцией, которая задает агенту строгую рабочую структуру через папки. У агента есть папки только для чтения (информация о пользователе, шаблоны, контекст проектов) и одна папка для записи -- туда он складывает результаты, создавая отдельную подпапку под каждую задачу. Агент не вправе ничего изменять за пределами папки с результатами.

Инструкцию можно положить в общие инструкции Claude (в настройках, раздел Instructions for Claude) или в инструкции проекта. Работает она, пока на компьютере открыт Claude Desktop и папки подключены.

```
GLOBAL INSTRUCTIONS

BEFORE EVERY TASK

1. Read everything in ABOUT ME/. No task starts without this.
2. If the task relates to a project, read everything in the matching PROJECTS/ subfolder before proceeding.
3. If the task involves a content type with a matching pattern in TEMPLATES/, study that template's structure first.
   Use the structure. Do not copy the content.

FOLDER PROTOCOL

Read-only — never create, edit, or delete here:
- ABOUT ME/    — My identity, style rules, writing examples.
- TEMPLATES/   — Proven structures to reuse as patterns.
- PROJECTS/    — My briefs, references, finished work by project.

Write folder — the only place you deliver work:
- CLAUDE OUTPUTS/ — Everything you create goes here.
  One subfolder per project, mirroring PROJECTS/ structure.
  Create the subfolder if it doesn't exist yet.

NAMING CONVENTION

All files you create must follow this format:
ProjectName_ContentType_v1.ext
Content types: Report, Brief, Letter, Draft, Analysis, Table, Deck.
Examples:
- ClientX_Report_v1.docx
- ProjectY_Brief_v1.md
- ContractZ_Analysis_v2.md
Increment version number if a file with the same name already exists.

OPERATING RULES

- If the brief is unclear or incomplete, use the AskUserQuestion tool. Do not fill gaps with generic filler or assumptions.
- Do not over-explain. Deliver the work. Save commentary unless I explicitly ask for it.
- Never delete files anywhere.
- Always confirm the plan before executing on complex tasks.
```

**Советы по работе с папками:**

-  Подключайте папку конкретного дела, а не весь диск: агент видит меньше лишнего и быстрее находит нужное.

-  Держите исходники и результаты в разных папках, как в инструкции выше, и делайте копию перед массовыми операциями.

-  Постоянные правила -- стиль, оформление, порядок проверки -- выносите в инструкции проекта, а не повторяйте в каждой задаче.

## Возможность Claude в приложении

1. **Документы, таблицы и презентации.** Claude возвращает готовые файлы -- `.docx`, `.xlsx`, `.pptx`, `.pdf` -- в разговор или в подключенную папку. Для совместной работы есть Claude Docs и Claude Slides: документ и презентация, которые вы правите вместе с Claude и показываете по одной ссылке, в том числе с телефона; слайды выгружаются в PowerPoint или PDF. Визуальные материалы делаются в [Claude Design](./../../instrumenty/vizualizatsiya-i-prezentatsii/claude-design). 

2. **Исследования.** Отдельного переключателя веб-поиска нет: Claude ищет в интернете, когда это нужно. Для глубокого исследования есть команда `/deep-research` или кнопка «+» в поле ввода. 

3. **Браузер.** Если для задачи нужен сайт, Claude открывает его во встроенном браузере десктоп-приложения или в вашем Chrome через Claude in Chrome. Встроенный браузер отделен от вашего: в нем свои входы на сайты, которые сохраняются между задачами, а сохраненные логины из обычного браузера можно импортировать по одному сайту. Claude in Chrome работает в вашем браузере под вашими учетными записями. 

4. **Управление компьютером** (Computer use). Когда для задачи нет коннектора, Claude может сам открывать приложения, кликать и печатать на экране. Это медленнее и менее надежно, чем работа через коннектор, поэтому управление компьютером -- запасной путь, а не основной.

5. **Задачи по расписанию.** Повторяющуюся работу можно поставить на расписание командой `/schedule` в любой задаче или в разделе Scheduled на боковой панели. 

6. **Инструкции и память.** Общие правила для всех задач задаются в настройках, в разделе Instructions for Claude, а правила по конкретному делу -- в инструкциях проекта. 

7. **Работа с телефона.** Задачу можно начать с телефона, следить за ходом, отвечать на вопросы агента и менять курс. Когда Claude закончил работу или ему нужно ваше решение, приходит уведомление.

8. **Интерактивные страницы.** Кроме файлов, Claude делает артефакты -- трекеры, дашборды, сводки, которые открываются на десктопе и в браузере.

**Советы из справки Anthropic:**

-  Связанную работу ведите в одной задаче, а для несвязанной начинайте новый разговор.

-  Если нужен быстрый ответ, а не файл, так и скажите: это экономит лимиты.

-  Вмешивайтесь по ходу работы: агента можно поправить, не дожидаясь конца задачи.

-  Расход лимитов виден в настройках, в разделе Usage.

## Claude Code: когда юристу нужен терминал

Claude Code -- тот же агентный движок в обвязке для разработчиков. Он работает в терминале, во вкладке Code десктоп-приложения, в браузере на claude.ai/code и в средах разработки (VS Code, JetBrains). Все эти окна используют один движок, поэтому инструкции, настройки и подключенные MCP-серверы у них общие. Для программирования Claude Code -- один из основных инструментов [вайб-кодинга](./../../instrumenty/vayb-koding/_index), но юристу он бывает полезен и для обычных задач.

**Когда он удобнее приложения:**

-  **Нужны постоянные инструкции в файле.** Правила проекта Claude Code читает из файла `CLAUDE.md` в папке; подходит и общий для разных агентов `AGENTS.md`. 

-  **Нужно больше контроля.** Режим плана показывает план до того, как агент тронет файлы; можно подтверждать каждое действие или разрешить агенту только правку файлов.

-  **Нужна другая модель.** Терминальную версию и расширения для сред разработки можно подключить не только к подписке Claude, но и к сторонним провайдерам моделей, включая совместимые API других разработчиков. 

 Проще всего начать со вкладки Code в Claude Desktop: устанавливать ничего не нужно, достаточно выбрать папку и начать с режима плана. Терминальная версия ставится одной командой из документации Claude Code. Что такое терминальные харнессы и как с ними работать -- в статьях [Инструменты](./../../instrumenty/vayb-koding/instrumenty) и [Кодинг с агентами](./../../instrumenty/vayb-koding/koding-s-agentami).

## Ограничения

-  Папки на компьютере, встроенный браузер и управление компьютером работают, только пока десктоп-приложение открыто и компьютер в сети.

-  Содержимое локальных файлов, которые агент открывает в приложении, обрабатывается на серверах Anthropic.

-  В длинных задачах история сжимается, и детали инструкций теряются. Методику надежнее держать в файлах -- подробнее в статье [Контекстная инженерия](./../upravlenie-agentami/kontekstnaya-inzheneriya).

-  В режиме Auto агент действует без подтверждений, поэтому перед работой с важными файлами стоит сделать копию.

-  Браузерный агент уязвим для скрытых инструкций на страницах.
