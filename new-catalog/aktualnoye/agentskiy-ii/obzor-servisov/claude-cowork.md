## Описание

**Тип:** десктопное приложение от Anthropic\
**Установка:** скачать в составе [приложения Claude](https://claude.ai/download)\
**Цена:** Pro $20/мес, Max от $100/мес\
**Запуск:** 12 января 2026\
**Платформы:** macOS (с запуска), Windows (с 3 апреля 2026)

Claude Cowork -- агент для работы с локальными документами. Вы даете ему доступ к папке на компьютере, описываете задачу -- дальше агент работает самостоятельно.

Ключевое отличие от обычного чата: документы не загружаются в контекстное окно целиком. Агент извлекает нужные фрагменты через векторный поиск ([RAG](../../upravlenie-dannymi-i-pamyatyu/rag)), работает с ними частями и создает промежуточные суммаризации -- это позволяет обрабатывать большие объемы документов без потери качества.

Агент запускается в изолированной Linux-виртуальной машине и ограничен только выбранной папкой. Часть операций (переименование, структурирование файлов) выполняется локально; часть данных передается на серверы Anthropic для обработки моделью.

**Плагины** (запущены 30 января 2026): каждый плагин включает скиллы, команды, MCP-коннекторы и субагентов. На старте Anthropic выпустила 11 официальных open-source плагинов, включая юридический; к 24 февраля каталог расширился еще на 12 -- для HR, инженерии, дизайна, операционной работы и финансовых услуг. Подробнее -- в статье [Скиллы и плагины](./../kastomizaciya-agentov/skills-i-plaginy).

**Ключевые расширения 2026 года:** в марте появилась Dispatch -- управление сессией Cowork с телефона; в апреле добавилось Computer Use -- агент работает с приложениями на компьютере без отдельной настройки. К ним добавились Scheduled Tasks (запуск задач по расписанию) и Projects в Cowork (постоянные рабочие пространства).

## Как ставить задачи в Cowork

Cowork выглядит интуитивно, но за простым интерфейсом скрывается агентная архитектура, которая требует осознанного подхода к постановке задач.

**Декомпозиция вместо одного большого промпта.** Сложные задачи лучше делить на последовательные этапы в отдельных чатах. Оркестратор разбивает задачу на подзадачи для субагентов, которые работают параллельно и изолированно -- без общей памяти. Если между частями задачи есть зависимости, параллельное выполнение без синхронизации создает противоречия.

**Контекст деградирует при компактинге.** При заполнении контекстного окна примерно на 80–85% система автоматически суммаризирует историю. Детали и точные формулировки при этом теряются. В многосоставных задачах с параллельными потоками компактинг происходит многократно -- инструкции могут существенно деградировать. Практический вывод: методику и ключевые критерии лучше разбивать на отдельные файлы, а не хранить в одном большом документе.

**Промежуточный контроль.** Для сложных проектов важно делать аудит после каждого этапа, а не ждать финального результата -- без промежуточных проверок ошибки каскадируются.

Подробнее об этом опыте -- в статье Екатерины Якуненко [«Claude Cowork: первое касание»](https://blog.delay-rag.ru/claude_cowork_first_touch/).

### Папочная архитектура: подход Константина Р.

Один из выпускников курса [«Нейросети для юриста: от основ к системе» ](https://runetlex-academy.ru/neuralnetworks)поделился системным промптом, который задает Cowork строгую рабочую структуру через папки. У агента есть папки только для чтения (информация о пользователе, шаблоны, контекст проектов) и одна папка для записи -- куда он складывает результаты, создавая отдельную подпапку под каждую задачу. Агент не вправе ничего изменять за пределами папки с результатами.

Промпт написан на английском -- Claude лучше следует инструкциям на языке, на котором обучался работать с командами.

```
GLOBAL INSTRUCTIONS

BEFORE EVERY TASK

1. Read everything in ABOUT ME/. No task starts without this.
2. If the task relates to a project, read everything in the matching PROJECTS/ subfolder before proceeding.
3. If the task involves a content type with a matching pattern in TEMPLATES/, study that template's structure first.
   Use the structure. Do not copy the content.

FOLDER PROTOCOL

Read-only — never create, edit, or delete here:
- ABOUT ME/    — My identity, style rules, writing examples.
- TEMPLATES/   — Proven structures to reuse as patterns.
- PROJECTS/    — My briefs, references, finished work by project.

Write folder — the only place you deliver work:
- CLAUDE OUTPUTS/ — Everything you create goes here.
  One subfolder per project, mirroring PROJECTS/ structure.
  Create the subfolder if it doesn't exist yet.

NAMING CONVENTION

All files you create must follow this format:
ProjectName_ContentType_v1.ext
Content types: Report, Brief, Letter, Draft, Analysis, Table, Deck.
Examples:
- ClientX_Report_v1.docx
- ProjectY_Brief_v1.md
- ContractZ_Analysis_v2.md
Increment version number if a file with the same name already exists.

OPERATING RULES

- If the brief is unclear or incomplete, use the AskUserQuestion tool. Do not fill gaps with generic filler or assumptions.
- Do not over-explain. Deliver the work. Save commentary unless I explicitly ask for it.
- Never delete files anywhere.
- Always confirm the plan before executing on complex tasks.
```

## Техники расширенного использования

### Интеграция с NotebookLM

NotebookLM можно подключить к Cowork как инструмент: агент сам обращается к вашим ноутбукам, добавляет источники и задает вопросы. Это позволяет разделить работу: тяжелую аналитику по большому массиву документов (30+ файлов, веб-исследования, кросс-референсы) берет на себя NotebookLM бесплатно, а Cowork тратит токены только на оркестрацию и финальный результат.

Для регулярной работы с большим корпусом документов разница в управлении контекстным окном принципиальная. По оценке Алексея Мынки, выпускника курса [«Нейросети для юриста: от основ к системе»](https://runetlex-academy.ru/neuralnetworks), один PDF на 20 страниц при загрузке в чат Claude съедает 30-60 тыс. токенов и платится заново при каждом follow-up; тот же документ через NotebookLM по MCP -- 500-2 000 токенов на запрос, и сам файл в контекст Cowork не попадает вообще.

Подключение -- одноразовая настройка из трех шагов: установить библиотеку `notebooklm-py` и авторизоваться в Google, поднять локальный MCP-сервер, подключить его к Cowork через плагин-обертку. Cowork, в отличие от Claude Desktop, не подключает «кастомные» MCP-серверы напрямую -- ему нужен плагин. Подробнее про способы установки плагинов -- в статье [Скиллы и плагины](./../kastomizaciya-agentov/skills-i-plaginy).

### MCP-сервер с нормативными актами

Степан Леонтьев подключил к Cowork MCP-сервер с базой российского законодательства -- Конституцией и кодексами. Агент обращается к ним напрямую как к инструменту, вместо того чтобы искать тексты законов в интернете.

Преимущества по сравнению с веб-поиском: агент не зависит от актуальности поисковой выдачи и не рискует получить ненадежный источник. База структурирована: у каждого документа есть оглавление и краткое резюме статей -- это позволяет модели сначала посмотреть структуру, а потом запросить конкретную статью, не перегружая контекстное окно целиком. К статьям можно дополнительно «прикреплять» комментарии, глоссы, собственные пометки.

### Еженедельный дайджест по EU Digital

Григорий Москалев [сделал](https://t.me/docsllm/65854) скилл для мониторинга регуляторики в сфере EU Digital. Скилл запускает поиск одновременно по семи блокам: законодательство, судебная практика, штрафы, стандарты, экспертные мнения и другие. На выходе -- структурированный дайджест, который собирается автоматически по расписанию.
