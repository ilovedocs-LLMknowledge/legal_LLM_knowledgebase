<note type="info">

MCP (Model Context Protocol) -- открытый стандарт для подключения AI-агентов к внешним системам. Благодаря MCP агент может работать с данными из CRM, почты, корпоративных баз данных -- через единый протокол вместо отдельной интеграции под каждый сервис.

</note>

**Дата составления:** 2026-05-03\
**Статус:** ✅ Актуально

---

## Суть

Агент умеет работать с инструментами -- но инструменты нужно как-то подключить. Раньше каждый разработчик делал это по-своему: писал собственный код для интеграции с Gmail, потом еще отдельный для Slack, потом для CRM. Каждое подключение -- уникальная работа.

MCP решает эту проблему. Это стандарт, который описывает общий язык между AI-агентом и внешними сервисами. Разработчик создает MCP-сервер для своего инструмента один раз -- и этот сервер начинает работать с любым агентом, который поддерживает MCP.

Anthropic опубликовала спецификацию MCP в конце 2024 года и сделала ее открытой. В декабре 2025 управление протоколом передано в Linux Foundation -- в фонд Agentic AI Foundation, соучрежденный совместно с Block и OpenAI при поддержке Google, Microsoft, AWS, Cloudflare и Bloomberg.

Сегодня MCP поддерживают Claude (чат, Cowork, Code, API), ChatGPT и десктопное приложение OpenAI, Codex, GitHub Copilot и Windows 11, Cursor, Windsurf, OpenClaw и многие другие инструменты. В официальном реестре протокола -- около 2000 серверов, в каталоге Claude -- более 75, в ClawHub OpenClaw -- более 3 200.

---

## Как это работает

MCP-сервер позволяет:

-  Подключаться к конкретному сервису (Gmail, Jira, Notion);

-  «Объявлять» агенту, какие функции доступны: прочитать письмо, найти документ, создать задачу;

-  Исполнять запросы от агента и возвращать результаты.

Агент не знает, как устроен Gmail внутри. Он просто видит, что через MCP-сервер ему доступны функции «прочитать письмо», «найти письма по теме», «отправить ответ» -- и вызывает их по мере необходимости.

Технически MCP-серверы делятся на два типа: **remote** (работают по HTTP/SSE на удаленном сервере, подключаются по URL) и **local** (запускаются локально на компьютере пользователя, передают данные через stdio). Remote-серверы проще в установке, local-серверы дают больше контроля над данными -- они никуда не уходят с устройства.

---

## Для чего это нужно в юридической работе

MCP превращает разрозненные корпоративные системы в единое рабочее пространство агента. Вместо того чтобы переключаться между интерфейсами и копировать данные вручную, агент сам забирает нужное из каждой системы.

Практически это означает, что агент может: получить задачу из системы управления проектами, открыть нужные документы из корпоративного хранилища, проверить историю переписки по делу, обратиться к базе нормативных актов, сформировать итоговый документ -- все в рамках одной сессии. Поскольку MCP -- общий стандарт, эти сценарии работают и в Claude (Cowork, Code, чат), и в Codex, и в OpenClaw -- меняется только интерфейс подключения.

Примеры существующих MCP-серверов: Google Drive, Gmail, Slack, Asana, Jira, GitHub, DocuSign, FactSet (финансовые данные), а также серверы [под российские ресурсы](https://neuraldeep.ru/mcp?filter=russian) -- от баз законодательства до 1С.

## Разница между MCP и плагином

MCP -- это протокол подключения. Плагин -- это формат пакетирования, который может включать MCP-сервер вместе со скиллами, командами и субагентами в единое решение. Плагины -- надстройка над MCP, не его часть. Подробнее о плагинах -- в статье [Скиллы и плагины](./skills-i-plaginy).
